# v0.2.0 — Kellogg fix for synth Nora's Admiration scene

## Problem
See `docs/analysis/03-synth-nora-kellogg-affinity-bug.md`. Synthetic Love's first-time Admiration scene is a
conversation about Kellogg's death, with no condition on Kellogg actually being dead.

## Confirmed from vanilla files
- **MQ106 stage 902** is Kellogg's death: it completes the "kill Kellogg" objective, starts `MQ106_NickKelloggDead`
  and fires the `COMQC_MQ106KelloggDeadAV` companion chat event. Nora Spouse conditions its own Kellogg line on the same stage.
- Vanilla `CompanionActorScript.ModAffinity` → `GetNextLockedThreshold`: a threshold whose `ConditionalGlobal` is
  set and `<= 0` is **locked**. Affinity is clamped to one point below it. Nothing is skipped or lost.
- `CA_T2_Admiration` (`0004B1C5`) = 500, `CA_Affinity` AV = `000A1B80`.
- Vanilla `CompanionActorScript.GetWithPlayerAffinityGain` gives every companion a small passive affinity tick for
  travelling with the player. That explains most of the "affinity rising on its own"; it's vanilla design, not a bug.

## Fix
New forms (ESL range):
- `GLOB 0x800 NN_SynthNora_AdmirationAllowed` = 0
- `QUST 0x801 NN_KelloggGate`, start-game enabled, script `NN_KelloggGateScript`

`NN_KelloggGateScript` (source in `tools/kellogg_gate.py`), on quest start:
1. Kellogg already dead (MQ106 stage 902 done) → stop, change nothing.
2. Synth Nora's affinity already ≥ Admiration → stop, change nothing (avoids pulling an existing save back down
   below Admiration, which would play her "going down" scene).
3. Otherwise set `ConditionalGlobal = NN_SynthNora_AdmirationAllowed` on her Admiration entry in
   `CompanionActorScript.ThresholdData_Array` at runtime, and listen for MQ106 stage changes.
4. Stage 902 → global set to 1, which unlocks Admiration. Her original Kellogg talk then plays the next time she crosses it.

The lock is applied at runtime rather than by overriding her NPC record because:
- script property values are stored in the save, so an NPC edit wouldn't reach existing saves
- an NPC override would impose one Synthetic Love version's loadout on all 8 versions

## How the script was built
There's no Creation Kit here, and Caprica only builds with MSVC, so the `.pex` is assembled directly:
- `tools/pex.py` reads and disassembles Fallout 4 `.pex` files
- `tools/pexw.py` writes them, including debug line info like CK output. Checked by exact round-trip on 53 existing
  scripts (vanilla, Nora Spouse and Synthetic Love)
- `tools/kellogg_gate.py` builds the script and holds the equivalent Papyrus source as a docstring

Instruction conventions (remote-event handler name `::remote_Quest_OnStageSet`, `struct_set` operand order,
`::nonevar`, property / auto-var layout) are copied from vanilla and Nora Spouse scripts.

## Installer
`Scripts/NN_KelloggGateScript.pex` is installed loose, always (FOMOD `requiredInstallFiles`). Both plugin variants carry the gate.

## Status
File-level verified only. In-game check:
- **New save:** raise synth Nora's affinity before Fort Hagen. It should stop at 499 (open the console, click her, type `getav CA_Affinity`).
  Kill Kellogg and it should then continue, and the Kellogg talk plays.
- **Existing save:** load the save with the patch installed. Nothing should change if she's already at Admiration.

## Random Encounter Framework (for the death site, later)
The example plugin adds an `SMQN` node whose parent is one of REFramework's branch nodes (e.g. `RESceneQuestsNIGHTParent`).
The encounter is a vanilla-style RE quest (`REScript` + `RETriggerScript`). REFramework masters all three DLCs, so the
death site will ship as a separate add-on plugin to keep `NoraAndNora.esp` DLC-free.
